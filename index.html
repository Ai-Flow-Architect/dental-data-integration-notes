2. お打ち合わせで確認させていただきたい事項（全5項目）
確認 ① ラボ管理ソフトに「取り込み口」があるか
読み取りの精度より先に、読み取った結果を受け取る側に入口があるかで実現方式が変わります。 国内で広く使われているラボ用受注販売管理ソフトの公開情報を確認したところ、動作環境は Windows 10/11 とされ、出力については次の記載がありました。 「すべての資料はＣＳＶ出力しエクセルでカスタマイズ」 一方で、取り込み（インポート）と API についての記載は公開情報に見当たりませんでした。 そこで、次の2点を先に確定させたいと考えております。
  • 画面に受注データを取り込むメニューがあるか
  • 開発元へ取込機能の有無・オプションを確認できる状態か（バージョンと保守契約）
→ この進め方でよろしいでしょうか？
確認 ② 入口が無かった場合、どこまで許容されるか
取り込み口が無い場合、代替は次の3つになります。
  • ア）開発元へ取込機能をオプションとして依頼する
  • イ）画面の操作そのものを自動化して入力する
  • ウ）中間ファイルを用意し、担当者が1操作で取り込む運用にする
イ）は動作しますが、ソフトの画面が更新されると止まりやすく、保守の前提が変わります。 先にご意向を伺えると、後戻りが起きません。 → ア〜ウのどれを想定されていますでしょうか？
確認 ③ スキャナ各社クラウドの認証方式と、規約上の可否
各社のクラウドから自動でデータを取得する場合、技術的にできるかとは別に、利用規約で自動ログイン・自動取得が認められているかを先に確認する必要があります。 また、多要素認証が有効になっている場合は自動化そのものが成立しません。
  • 各社の利用規約に自動アクセスの制限があるか
  • 多要素認証・IP制限の有無
  • 公式に連携手段（API・パートナー向けの仕組み）が用意されていないか
規約上できないものを作ってしまうと、完成後に使えなくなります。ここは着手前に潰しておきたい点です。 → 各社の規約と認証方式を確認するお時間をいただけますでしょうか？
確認 ④ 設計ソフトへの受け渡し方式
取得したデータを設計ソフトへ渡す部分は、受け取る側が何を受け付けるかで作り方が決まります。 フォルダに置く形か、専用の取り込み機能か、パートナー向けの連携手段があるかで工数が変わります。 → 受け渡し先として想定されているソフトと、その連携手段を教えていただけますでしょうか？
確認 ⑤ 材料計測データは、何をどこまで残すか
計測器がPCに繋がるかどうかで、難易度が3段階に分かれます。
  • ア）機器から直接データを取得できる
  • イ）機器が出力するファイルを読む
  • ウ）担当者が数値を入力する
あわせて、残す目的（原価の把握・使用履歴の追跡・在庫の管理）によって、持つべき項目が変わります。 → 現在の測り方と、残したい目的を教えていただけますでしょうか？
3. 進め方のご提案（段階を分ける）
手順 内容 区分
①現地で実機を確認し、取り込み口の有無と認証方式を確定させる確認
②確認結果をもとに、実現方式と必要な工数を確定する確認
③最も効果の大きい1機能から試作する開発
④試作をご確認いただき、方式を確定する確認
⑤残りの機能を開発する開発
⑥現地に配置し、実際の業務データでテストする現地
⑦運用開始・調整運用
なぜ段階を分けるか：①で入口の有無が変わると、実現方式そのものが変わります。 確認の前に全体を確定させてしまうと、後から作り直しになり、かえって時間がかかります。 逆に①②が終われば、その後は見通しが立った状態で進められます。
4. 当方の対応範囲（現時点の想定）

想定に含まれるもの

  • 現地での業務確認・ヒアリング
  • 読み取りと連携部分の開発
  • 動作テスト・精度の調整
  • 現地への配置と立ち会い
  • 操作手順書の作成

想定に含まれないもの

  • ラボ管理ソフト本体の改修（開発元の領域）
  • 各クラウドサービスの利用料・アカウント取得
  • 利用規約上できない自動化
  • 計測機器・PC等のハードウェア購入
・ご満足いただけなければ全額返金いたします
上記は現時点の想定です。確認①〜⑤の結果によって範囲は変わりますので、確定は条件が揃ってからとさせてください。
